# BASE eBay Sync: 特商法の開示請求方式

## 掲載方針
- サイトの `/legal/` には、販売事業者の氏名・名称、所在地、電話番号について「請求があった場合に遅滞なく開示します」と掲載する。
- メールアドレス、料金、決済、提供時期、解約・返金条件等は引き続き公開する。
- トップのフッターから `/legal/` に移動できる状態を維持する。
- `/privacy/` でも運営者の名称と住所を請求で案内する旨を表示する。

## 必須の運用手順
1. 商用公開前に、受信可能で日常的に確認するメールアドレスをGitHub Environmentの `LEGAL_EMAIL` に設定する。
2. 氏名（個人の場合は原則として戸籍上の氏名または登記された商号）、現に事業を行う正確な住所、確実に連絡できる電話番号を、公開リポジトリ・公開フロントエンド・CIログとは別の安全な場所で保管する。
3. 件名「特定商取引法に基づく事業者情報の開示請求」が届いたら、契約の申込みを判断する前に十分な時間的余裕ができるよう、電子メール等で氏名・名称、住所、電話番号を **遅滞なく** 全て提供する。確認のために不要な個人情報や購入履歴の提出を求めない。
4. 同様に個人情報保護法32条の事業者情報等の請求にも対応する。
5. 返信が確実に届くことを公開前にテストし、迷惑メール・不達・長期不在時のバックアップ対応を整備する。
6. Stripeの事業者確認、領収書、カード明細、各連携先の審査・規約は別途確認する。特商法の表示省略だけでは他の開示義務がなくなるわけではない。

## 設定とセキュリティ
- `apps/admin` は `output: "export"` の静的サイト。ビルド時の `NEXT_PUBLIC_*` 値は公開物に含まれる前提で扱う。
- `NEXT_PUBLIC_LEGAL_EMAIL` のみ公開する。氏名・住所・電話番号を `NEXT_PUBLIC_*`、ソース、README、Issue、CIログに書かない。
- `deploy.yml` は本番リリース前に `LEGAL_EMAIL` の設定を確認するが、実際に受信・返信できることや、非公開の事業者情報が正確であることは**自動検証しない**。
- すでに外部へ公開した個人情報は今回のコード変更だけでは外部キャッシュや過去の配信物から削除できない。
